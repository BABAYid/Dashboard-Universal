# Архитектура системы: приборка + мультимедиа

Документ фиксирует **из каких устройств состоит система, как они связаны, кто
чем владеет** и что происходит при отказах. Начатый 17.10.2026, переписан
6.11.2026 после решений по мультимедиа.

Пометки: ✅ — решение принято и не обсуждается, ❓ — открытый вопрос.

## 1. Общая картина

```
                    провода машины (разъём X1)
                            │
                            ▼
                ┌───────────────────────────┐
                │   БЛОК СБОРА (ESP32)      │
                │ входы: 23 дискретных,     │
                │ 4 аналоговых, частота;    │
                │ GPS NEO-M8N               │
                └───────────┬───────────────┘
                            │
        ── CAN 500 кбит/с (одна витая пара, 2×120 Ом) ────────────
             │                        │                    │
             ▼                        ▼                    ▼
   ┌──────────────────┐   ┌───────────────────┐   ┌──────────────────┐
   │ ESP32 ДЖОЙСТИКА  │   │ ESP32 КЛИМАТА     │   │ USB-CAN (gs_usb) │
   │ BMW iDrive       │   │ чтение родной     │   │      │           │
   │ кнопки, энкодер  │   │ панели + эмуляция │   │      ▼           │
   │ → кадр 0x530     │   │ кнопок (оптроны)  │   │ ┌──────────────┐ │
   └──────────────────┘   │ → 0x510, ← 0x540  │   │ │  ПРИБОРКА    │ │
                          └──────────┬────────┘   │ │ RK3588 022A  │ │
                                     │ провода    │ │ Qt/QML       │ │
                                     ▼            │ │ LVDS 1920×720│ │
                          (родная панель климата:  │ │ P1230FHF1MAAA│ │
                           продолжает управлять    │ └──────┬───────┘ │
                           заслонками сама)        └────────┼─────────┘
                                                           │ Ethernet 1G
                                                           │ (прямой кабель,
                                                           │  статические IP)
                                                           ▼
                                              ┌──────────────────────────┐
                                              │ МУЛЬТИМЕДИА RK3588 022A  │
                                              │ Android 12               │
                                              │ экран 13.3–15.6″ + USB-  │
                                              │ HID тач, свой GPS 10 Гц  │
                                              │ навигация, медиа, климат │
                                              └──────────────────────────┘
```

Отдельно, **не** на этой шине: ESP32 селектора АКПП (`AKPP_Selector`) со своей
парой к BMW-рычагу. Причина — в его прошивке приём устроен как один кадр за
итерацию; чужой трафик приборной шины переполнит его очередь и рычаг может
потерять положение. Железная развязка дешевле, чем риск.

## 2. Устройства и роли

| Устройство | Что делает | Чего не делает |
|---|---|---|
| **Блок сбора** (ESP32, `firmware/`) | Читает провода машины, GPS; отдаёт кадры `0x100…0x521`, `0x7F0` | Не рисует, не хранит медиа |
| **Приборка** (RK3588 022A) | Приборы, карта, камеры; **разбор CAN и раздача данных по сети**; сторожевые функции | Не управляет климатом, не хранит медиа |
| **Мультимедиа** (RK3588 022A, Android 12) | Навигация, музыка/радио, климат-UI, камера; вход в интернет | Не читает провода машины, не жмёт кнопки климата напрямую |
| **ESP32 джойстика** (`firmware/joystick/`) | Держит BMW-джойстик живым (heartbeat, пробуждение), публикует `0x530` | Не решает, что делать с нажатием |
| **ESP32 климата** (не начат) | Читает состояние родной панели, эмулирует её кнопки; `0x510` наружу, `0x540` внутрь | Не управляет заслонками и вентилятором — это делает родной блок |

Ключевые правила:

1. **Физика машины — в микроконтроллерах, интерфейс — в Linux/Android.**
2. **Приборка автономна.** Падение, перезагрузка или отсутствие мультимедиа
   не должны лишать водителя показаний. Навигационные подсказки, климат и
   медиа — улучшения, а не критический путь.
3. **Один поток — один владелец.** Никто, кроме блока сбора, не читает провода
   машины; никто, кроме мультимедиа, не хранит медиа; климат читает и жмёт
   ровно один ESP32.

## 3. Связи между устройствами

| Откуда → куда | Чем | Зачем |
|---|---|---|
| Блок сбора → все | **CAN 500 кбит/с** | Данные машины, GPS |
| ESP32 джойстика → приборка | CAN (`0x530`) | Нажатия кнопок и энкодер |
| ESP32 климата ↔ приборка | CAN (`0x510` наружу, `0x540` внутрь) | Состояние климата и команды |
| Приборка → ESP32 климата | CAN (`0x540`) | «Нажми кнопку»: температура, вентилятор, режим |
| Приборка ↔ мультимедиа | **Ethernet 1G**, прямой кабель, статические IP `10.0.0.1` / `10.0.0.2` | Данные машины, климат, подсказки навигации, события джойстика; медиа — в обратную сторону |
| Мультимедиа → динамики | усилитель (8R/5W на плате или линейный выход) | Звук |
| Мультимедиа ← камера | USB | Задний ход / регистратор |
| Экран приборки ← 022A | LVDS 2-port 1920×720 (кабель + LVDS-адаптер из комплекта) | Панель P1230FHF1MAAA, 12.3″ |
| Экран мультимедиа ← 022A | eDP/LVDS/HDMI + USB-HID тач | Панель 13.3–15.6″ ✅ |

### Шины

- **Приборная CAN** — одна витая пара, 500 кбит/с, все узлы с 11-битными ID.
  Терминаторы ровно два: на концах пары (не три — у USB-адаптера свой
  переключатель, его надо выключить, если он не крайний).
- **Шина АКПП** — отдельная пара, только ESP32 селектора и BMW-рычаг.
- **Ethernet** — прямой кабель между двумя 022A. Коммутатор не нужен; если
  позже появится третий сетевой узел — поставить пятипортовый.

## 4. Владение данными

| Данные | Владелец | Кто использует |
|---|---|---|
| Скорость, обороты, лампы, датчики, газ | блок сбора | приборка, мультимедиа (через приборку) |
| Состояние климата | ESP32 климата | приборка (разбор `0x510`), мультимедиа (через приборку) |
| Команды климату | мультимедиа (источник) → приборка (шлюз) → ESP32 климата (исполнитель) | — |
| GPS 1 Гц | блок сбора | приборка: камеры, карта, время |
| GPS 10 Гц | мультимедиа (свой приёмник) | навигация на Android |
| Время | приборка (GPS) | мультимедиа синхронизируется |
| Медиа | мультимедиа | приборка (виджет «сейчас играет») |
| Навигационные подсказки | мультимедиа | приборка (компактная стрелка + расстояние + ограничение) |
| Ввод с джойстика | ESP32 джойстика | приборка и мультимедиа — по правилу фокуса (см. §6) |
| Интернет | мультимедиа (4G) ❓ | приборка (карта, время) |

## 5. Протоколы

### CAN (протокол 1.4, `can_protocol_v1.4.txt`)

| ID | Кто шлёт | Период | Содержимое |
|---|---|---|---|
| `0x100` | блок сбора | 50 мс | скорость, обороты |
| `0x200` | блок сбора | 50 мс | свет и лампы |
| `0x300` | блок сбора | 50 мс | датчики, расход |
| `0x400` | блок сбора | 50 мс | АКПП |
| `0x500` | блок сбора | 200 мс | газ |
| `0x510` | **ESP32 климата** | 200 мс | состояние родной панели |
| `0x520` / `0x521` | блок сбора | 500 мс | GPS |
| `0x530` | ESP32 джойстика | по событию | кнопки и энкодер |
| `0x540` | приборка | по событию | ❓ команды климату (новый кадр, протокол 1.5) |
| `0x7F0` | блок сбора | 1000 мс | статус блока |

**Переход владельца `0x510`:** сейчас кадр собирает блок сбора (и всегда с
`valid = false`). Когда появится ESP32 климата, блок сбора перестаёт его
слать — формат не меняется, меняется только передатчик. Двух передатчиков
одного ID на шине быть не должно.

### Сеть (приборка ↔ мультимедиа)

Приборка — HTTP/WebSocket-сервер на `10.0.0.1`, мультимедиа — клиент:

- `GET /api/car` — скорость, обороты, датчики, лампы;
- `GET /api/climate` — состояние климата; `POST /api/climate` — команда;
- `GET /api/gps` — координаты (1 Гц, для карты приборки);
- `GET /api/nav` — подсказки навигации (манёвр, расстояние, ограничение);
- `WS /api/input` — события джойстика мультимедиа (вниз), и события Android
  на приборку: переключение вида, статус «в сети»;
- `GET /api/media` — **в обратную сторону**: приборка спрашивает у мультимедиа,
  что играет (уже реализовано в `MediaBackend`).

Полный контракт (поля, единицы, частоты, коды ошибок) — отдельный документ
`docs/integration.md`, ❓ написать до начала мультимедиа.

## 6. Ввод: джойстик и маршрутизация фокуса

Джойстик BMW iDrive стоит в тоннеле. Его события (`0x530`) приходят на
приборку первой — она уже умеет их принимать.

Правило маршрутизации (❓ предлагается, нужно подтвердить):

1. Если у приборки открыт **свой** интерактивный слой (настройки, навигация) —
   события обрабатывает она.
2. В остальное время приборка **пересылает** события мультимедиа по
   `WS /api/input`: пусть тач-интерфейс листается джойстиком.
3. Аппаратные кнопки NAV, BACK, OPTION остаются за приборкой всегда: это
   переключение видов самой приборки, а не мультимедиа.

Плюс такого правила: одна точка решения (приборка), мультимедиа не нужен
собственный CAN, а при выключенном Android джойстик всё равно листает
режимы приборки.

## 7. Питание и порядок запуска

Все устройства питаются от **12 В через ACC**, общий минус — в одной точке
кузова.

```
ACC ──► [плата питания: защита, DC-DC, задержка выключения] ❓
          ├──► блок сбора (12 В)
          ├──► ESP32 джойстика и климата (12 → 5 В)
          ├──► приборка (12 В)
          └──► мультимедиа (12 В)
```

**Задержка выключения.** 022A не умеет «вежливо» гаснуть при пропадании
12 В, а Linux и тем более Android нужны 10–20 секунд. Решение (❓ делать
своей платой или брать готовый автомобильный delayed-off модуль): супервизор
даёт сигнал «засыпай», приложения закрываются, питание снимается через
20–30 секунд.

**Порядок после ACC:** блок сбора готов <1 с → приборка показывает данные
через 3–5 с → ESP32 джойстика и климата сразу → Android 25–40 с. Поэтому
подсказки навигации и медиа «догоняют», а приборы не ждут никого.

## 8. Отказы

| Что отказало | Что работает | Что видит водитель |
|---|---|---|
| Блок сбора | приборка и мультимедиа живы | «НЕТ ДАННЫХ CAN», приборы в нуле |
| Приборка (CAN-адаптер) | — | приборка без данных; мультимедиа работает само |
| Мультимедиа | приборка полностью, климат родными кнопками | пропали подсказки навигации и медиа-виджет; джойстик листает только режимы приборки |
| ESP32 климата | родная панель работает кнопками | в Android «климат недоступен», управления нет |
| ESP32 джойстика | всё остальное | джойстик не реагирует (и, возможно, не светится) |
| Приборка целиком | мультимедиа автономно, родной климат работает | нет приборов |
| Ethernet-кабель | обе стороны работают отдельно | «нет связи» на приборке, нет климата в Android |

Правило: **любой отказ не блокирует машину.** Родные кнопки, родной климат и
приборные данные не зависят ни от сети, ни от Android.

## 9. Комплект (что уже есть)

- **Экран приборки:** P1230FHF1MAAA — 12.3″, 1920×720, 2-port LVDS (VESA);
  LVDS-адаптер, кабель и power set — в папке `комплект подключения`.
- **Платы:** 2 × BTP-PCM-A-022A (RK3588), даташит в корне репозитория.
- **USB-CAN:** адаптер на STM32F072 с изолированным ADM3053, прошивка
  candleLight (`gs_usb`) — даёт `can0` в Linux.
- **Джойстик BMW iDrive** (F20) + ESP32 + SN65HVD230 — прошивка готова.
- **Экран мультимедиа** 13.3–15.6″ с USB-HID тачскрином — не выбран.

## 10. Что нужно решить

1. **Плата питания с задержкой:** своя (МК + ключи) или готовый автомобильный
   delayed-off модуль?
2. **Кадр `0x540` — команды климату:** нужен ещё до появления ESP32 климата,
   чтобы прошивка и интерфейс делались по одному документу (протокол 1.5).
   Спроектировать с подтверждением: команда → ESP32 нажал → панель реально
   изменилась → `0x541` со новым состоянием.
3. **Кнопки родной панели климата:** это отдельные провода (шунтируются
   оптронами) или резистивная матрица/шина? От этого зависит объём работ.
4. **Интернет раздаёт мультимедиа** (4G) приборке — подтвердить по трафику
   и по тому, умеет ли Android-прошивка отдавать Ethernet как роутер.
5. **Фокус ввода** (правило §6) — согласовать.
6. **Джойстик и климат на одной ESP32 или на двух** в тоннеле: две платы —
   изоляция отказов, но два корпуса и два жгута; одна — компактнее.
