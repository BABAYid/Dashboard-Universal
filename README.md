# Приборная панель (Audi Dashboard)

Виртуальная приборная панель для автомобиля: Qt6/QML-интерфейс на nanoPC-T6 (RK3588),
данные приходят по CAN от блока сбора на ESP32.

```
ESP32 (сбор сигналов)  ──CAN 500 кбит/с──►  nanoPC-T6 (SocketCAN)  ──►  Qt6/QML приборка
```

## Структура

| Путь | Что это |
|---|---|
| `Dashboard/` | Приложение Qt6/QML |
| `Dashboard/Main.qml` | Компоновка макета 1920×720, привязка данных к бэкенду |
| `Dashboard/Speedometer.qml`, `Tachometer.qml` | Приборы (стрелки, шкалы) |
| `Dashboard/Indicators.qml` | Лампы, наружная температура, одометр/trip |
| `Dashboard/Settings.qml` | Окно калибровки коэффициентов |
| `Dashboard/MapWebView.qml` | Карта (OpenStreetMap) в режиме навигации |
| `Dashboard/can/CanBackend.*` | Приём CAN, разбор протокола, демо-режим |
| `Dashboard/tests/` | Тест разбора протокола |
| `can_protocol_v1.txt`, `CAN_protocol_v1.0.odt` | Описание CAN-протокола |
| `esp32_wiring.txt` | Таблица подключения сигналов к ESP32 |
| `Приборная панель/` | Исходники дизайна (в т.ч. макет `Group 57.png`) |
| `образ для nanoPC-T6/` | Образы ОС для устройства (в git не хранятся) |

## Сборка

Нужен Qt 6.8+ с модулями Quick и WebView.

```bash
cmake -S Dashboard -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
```

## Запуск

```bash
./build/appDashboard --mock          # демо-режим: данные генерируются, CAN не нужен
./build/appDashboard --can can0      # приём реальных кадров с интерфейса can0
./build/appDashboard --fullscreen    # для установки в автомобиль (без рамки)
```

Отладочный снимок экрана (удобно на устройстве без монитора):

```bash
DASHBOARD_SHOT=/tmp/dash.png ./build/appDashboard --mock
```

## Подготовка CAN на устройстве

```bash
sudo ip link set can0 up type can bitrate 500000
candump can0            # посмотреть, что приходит от ESP32
ip -details link show can0
```

Если интерфейс появится позже запуска приборки, приложение само подключится
к нему в течение 5 секунд. При отсутствии кадров дольше 1,5 с на экране
загорается предупреждение «НЕТ ДАННЫХ CAN».

## Протокол

Версия 1.0, классический CAN, 11-битный ID, 8 байт данных, 500 кбит/с.
Полное описание — `can_protocol_v1.txt`.

| ID | Содержимое |
|---|---|
| `0x100` | скорость (байт 0), обороты (байты 1–2, uint16) |
| `0x200` | байт 0 — свет (поворотники, дальний, ближний, габариты, туманки, задний ход, стопы); байт 1 — индикаторы (чек, ABS, ручник, ремень, давление масла, LOCK) |
| `0x300` | температура двигателя, уровень топлива, напряжение ×10, наружная температура (int8), авария по маслу, расход ×10 |
| `0x400` | режим АКПП (P/R/N/D/L), номер передачи, LOCK, провода S1/S2/SL |

Разбор реализован в `Dashboard/can/CanBackend.cpp` и покрыт тестами:

```bash
cmake -S Dashboard -B build -DDASHBOARD_BUILD_TESTS=ON
cmake --build build --target test_canprotocol
./build/test_canprotocol
```

## Лампы и индикаторы

Все лампы управляются данными из CAN и по умолчанию погашены:

| Лампа | Условие |
|---|---|
| Поворотники | мигают 1,5 Гц, пока приходит соответствующий бит `0x200` |
| Дальний свет, габариты, противотуманки | соответствующие биты `0x200` |
| Ремень | бит «не пристёгнут» `0x200` |
| Ручник | бит ручника `0x200` |
| ABS, Check Engine, давление масла | биты `0x200` |
| Топливо | уровень ≤ 10 % (`0x300`) |
| Зарядка АКБ | двигатель работает (обороты > 400), а напряжение < 12,8 В |
| Перегрев двигателя | температура ≥ 110 °C (`0x300`) |

При включении зажигания все лампы горят 2,5 с (самопроверка), стрелки
проходят полную шкалу.

## Коэффициенты калибровки

Двойной клик по центральной области открывает окно калибровки (скорость,
обороты, топливо, температура). Значения сохраняются и применяются при запуске.
Долгое нажатие по центральной области — режим навигации (карта).
Долгое нажатие на одометре — сброс текущего trip.

## Что ещё не сделано

- Прошивка ESP32 (в репозитории только описание протокола и таблица пинов).
- Таблица пинов `esp32_wiring.txt` содержит ошибки: занятые флешем GPIO 6–11,
  не-АЦП пины 21/22 под аналоговые датчики, strapping-пины под входы.
- В `0x300` байт 5 (расход) объявлен как uint8 при заявленном диапазоне
  0–99.9 л/100 км ×10 — диапазон не помещается, нужен uint16.
- Нет кадра-признака жизни: признаки устаревания данных есть, а понять, что
  блок сбора перезапустился, нельзя.
- Автозапуск, kiosk-режим и настройка SocketCAN на устройстве.

## Важные особенности реализации

- `CanBackend` — QML-синглтон. Его конструктор **намеренно объявлен без
  аргумента по умолчанию**: Qt при регистрации синглтона сначала проверяет
  возможность создать объект конструктором по умолчанию и только потом —
  статический `create()`. Если класс default-constructible, QML создаст второй
  экземпляр, и данные в приборку не попадут (молча, без ошибок в логе).
- Анимации стрелок пишут в отдельное свойство `sweepAngle`, а не в `rotation`:
  запись в привязанное свойство разрушает привязку, и стрелка «застывает».
- Абсолютных путей к файлам быть не должно — только ресурсы QML-модуля.
