# Прошивка блока сбора (ESP32)

Блок сбора читает провода автомобиля и отправляет данные по CAN в приборку
(RK3588, `appDashboard`). Протокол — `can_protocol_v1.2.txt`, версия прошивки
1.2. Плата — своя: `Схема принципиальная.pdf` (Altium, 13.10.2026) и Gerber
в `rezonit/` (08.09.2026).

```
провода машины ──► оптопары / ADS1115 ──► ESP32 ──CAN 500 кбит/с──► приборка
```

## Что уже есть и чего нет

Сделано:

* чтение 23 дискретных входов 12 В (`DIN_1…DIN_23`) с антидребезгом;
* чтение 4 аналоговых входов (`AIN0…AIN3`) через ADS1115 (16 бит, I2C);
* измерение частоты на дискретных входах (спидометр, тахометр, при наличии —
  сигнал расхода от ЭБУ);
* сборка и отправка всех кадров протокола 1.2: `0x100`, `0x200`, `0x300`,
  `0x400`, `0x500`, `0x7F0` — с периодами 50/50/50/50/200/1000 мс;
* восстановление шины после bus-off (обрыв провода, выключенная приборка);
* **сон по зажиганию**: когда ACC гаснет, кадры прекращаются, а через 20 с блок
  уходит в глубокий сон и просыпается по тому же входу ACC (не сажает АКБ);
* драйвер проводов «на массу» (ручник, давление масла, ремень): внешняя
  подтяжка + инверсия по флагу в таблице проводов;
* пассивный сниффер K-линии — чтобы определить протокол ЭБУ по дампу;
* отладочная печать состояния раз в секунду (на столе видно, какой вход сработал).

Не сделано (осознанно, ждёт решения или железа):

* **таблица проводов не заполнена** — какой провод машины на какой вход
  посажен, знает только владелец; заполняется в `main/vehicle_signals.h`,
  после этого все значения появляются сами;
* **протокол K-линии (данные ЭБУ)** — сначала снимаем дамп сниффером, потом
  пишем разбор: от протокола (KWP1281 / KWP2000 / OBD-II по K-линии) зависит
  весь код, угадывать нельзя;
* GPS (GY-GPSV3-NEO-M8N) — NMEA не разбирается, и в протоколе 1.2 **нет кадра
  с координатами**: без него приборке нечего показывать на карте. Нужен
  протокол 1.3 с кадром положения (см. «GPS и навигация» ниже).

драйвер отдаёт привычное «1 = сигнал есть».

## Сборка и прошивка

Тулчейн ESP-IDF 5.5.6 стоит рядом с проектом — в папке `.dsh-idf/` (она
в `.gitignore`, в репозиторий не попадает). Если работаете не из песочницы
DeepSeek Harness, домашний каталог доступен и настройки путей не нужны:

```bash
# один раз: ESP-IDF 5.5
#   https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32/get-started/
. $IDF_PATH/export.sh

cd firmware
idf.py set-target esp32
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor
```

В песочнице (запись в домашний каталог запрещена) нужно указать пути иначе —
кэш менеджера компонентов тоже переносится в проект:

```bash
export IDF_PATH="$PWD/.dsh-idf/esp-idf-v5.5.6"
export IDF_TOOLS_PATH="$PWD/.dsh-idf/tools"
export IDF_COMPONENT_CACHE_PATH="$PWD/.dsh-idf/component-cache"
. "$IDF_PATH/export.sh"
cd firmware && idf.py build
```

**Проверено 16.10.2026:** прошивка собирается под esp32, предупреждений
компилятора нет (`-Wall -Wextra` включены для компонента `main`),
`dashboard_collector.bin` — 190 КБ, свободно 82 % раздела приложения.
На живой плате не запускалась: плата ещё не пришла.

Проверка без железа и без ESP-IDF — кодировщик кадров и таблица проводов
собираются обычным gcc и сверяются с документацией:

```bash
cmake -S firmware/test -B firmware-build
cmake --build firmware-build
./firmware-build/test_frames     # байты кадров против примеров из протокола
./firmware-build/test_signals    # таблица проводов: диапазоны и коллизии
```

Тест приборки (разбор тех же кадров) — `Dashboard/tests/test_canprotocol.cpp`,
запуск описан в `PROJECT_STATE.md`.

## Как заполнить таблицу проводов

Пока провода не назначены, блок работает, но в кадры уходит 0 либо нейтральное
значение-заглушка (чтобы приборка не показывала ложных предупреждений).

1. Взять список проводов от старой приборки: контакт разъёма → сигнал →
   **как он работает электрически**.
2. В `main/vehicle_signals.h` у нужного сигнала проставить `source`
   (`SRC_DIN` / `SRC_PCF` / `SRC_AIN` / `SRC_FREQ`), `channel` (номер `DIN_n`
   или `AIN_n`) и `x1_pin` (контакт разъёма, для читаемости таблицы).
3. Для частотных входов заполнить калибровки в `main/config.h`:
   `SPEED_IMPULSES_PER_KM`, `RPM_IMPULSES_PER_REV` — только замером на машине.
4. Для аналоговых датчиков заполнить точки калибровки в `main/config.h`
   (`FUEL_EMPTY_MV` / `FUEL_FULL_MV`, `TEMP_*`, `VOLTAGE_*`).

Пример заполненной строки:

```c
{ SIG_LEFT_TURN, "левый поворотник", 29, SRC_DIN, 1, 0, 30,
  "плюс 12 В при включении" },
```

## Грабли, которые надо помнить

### 1. Подтяжка на GPIO12 (I2C-2 SDA) — плата с ней не стартует

`I2C_2_SDA` посажена на **GPIO12 (MTDI)** — это strapping-вывод. Высокий
уровень на нём в момент включения переключает питание флеш-памяти на 1.8 В,
и модуль ESP32 не запускается. На плате на этой линии стоит подтяжка
4.7 кОм на +3.3 В (R3, `RC0805FR-074K7L`).

Что делать (плата уже заказана, переделывать дорожки не нужно):

* **R3 не запаивать.** В firmware подтяжка SDA включается программно
  (внутренняя ~45 кОм, `flags.enable_internal_pullup` в `inputs_digital.c`).
  При 100 кГц и коротких дорожках внутри платы этого достаточно;
* подтяжка на `SCL` (R4, GPIO14) безопасна — её оставить;
* подтяжку на линии прерывания PCF8574 (R5) — по решению, см. п. 5.

### 2. Провода «на массу» решаются одним резистором на канал

Схема входа: провод → 1 кОм → светодиод оптопары → **земля платы**. Провод,
который замыкается на массу (ручник, аварийное давление масла, ремень,
концевики), поэтому читается наоборот: пока он замкнут — светодиод погашен.

Решение без переделки платы: **подтяжка 4.7 кОм между проводом и +12 В**
(лучше от цепи ACC — тогда на стоянке не потребляет). Тогда:

| Состояние провода | Что видит вход платы | Что показывает прошивка |
|---|---|---|
| замкнут на массу (сигнал есть) | пассивен | сигнал есть |
| отпущен (сигнала нет) | активен | сигнала нет |

Прошивка инвертирует такой вход — за это отвечает флаг
`SIG_FLAG_GROUND_SWITCHED` в таблице проводов (у ручника, ремня и давления
масла он уже выставлен). Ток: при замкнутом концевике через подтяжку течёт
2.5 мА на канал.

Альтернатива без инверсии — переделка канала: катод светодиода отрезать от
земли платы и завести на провод машины, анод через 1 кОм — на +12 В (две
перемычки на канал). Ток тогда течёт только при активном сигнале. Если
переделывать канал — флаг в таблице надо снять.

### 3. Аналоговые входы: нужен источник напряжения, а не сопротивление

`AIN0…AIN3` — делитель 130 кОм / 27 кОм с защитой SMBJ3.3A. Вход измеряет
**напряжение 0…12 В** (для канала газа в схеме помечено «ЛИНИЯ 5В»).

Датчик уровня топлива (реостат на массу) и терморезисторы (температура
двигателя, наружная) дают не напряжение, а сопротивление. Чтобы их прочитать,
на провод датчика нужно подать питание через резистор-подтяжку: тогда
напряжение на проводе будет зависеть от сопротивления датчика. Без подтяжки
на входе будет почти ноль в любую погоду.

Варианты: внешний резистор от +5 В к проводу датчика (проще всего),
либо доработка платы. Номинал подтяжки выбирается под диапазон датчика;
калибровка — точками в `config.h`.

Если по K-линии удастся читать температуру двигателя из ЭБУ, этот вход
понадобится только под топливо.

### 4. GPS висит на UART0 — вместе с консолью и загрузчиком

По схеме GPS подключён к `UART0` (`GPIO1`/`GPIO3`). На этих же линиях —
USB-переходник DevKit'а: он используется и для прошивки, и для консоли.
Передатчик GPS и передатчик USB-переходника окажутся на одной линии.

Практика: **при прошивке GPS отключать** (достаточно его провода TX).
В машине USB не подключён, конфликта нет, но и консоль недоступна — отладка
только на столе. См. «GPS и навигация» ниже: сам модуль нужен, но протокол
для него ещё не расширен.

### 5. K-линия: сначала дамп, потом код

Железо готово (MC33290 + SN74LVC2T45 + `UART2`), в прошивке включён пассивный
сниффер (`KLINE_ENABLED = 1` в `config.h`). Порядок работы:

1. подключить блок к K-линии машины (контакт 3 разъёма X1, провод «ISO»);
2. запустить свой диагностический сканер (VCDS / Ваг-Ком / ELM327) и дать ему
   поработать — блок в это время слушает линию и печатает байты в консоль;
3. по дампу видно скорость, инициализацию, структуру блоков и адрес ЭБУ —
   после этого пишется разбор протокола (KWP1281, KWP2000 или OBD-II).

Сниффер в линию ничего не передаёт, поэтому сканеру не мешает.

### 6. Согласование CAN

Шина отдельная: ESP32 ↔ приборка. По 120 Ом на обоих концах между CAN_H (P)
и CAN_L (N). Без второго узла (или без резистора на стороне приборки)
контроллер уходит в bus-off — это нормально на столе, прошивка сама поднимает
шину заново.

### 7. Питание на стоянке и сон по зажиганию

В схеме нет отключения по зажиганию: `+VBAT` → MP1584EN (12→5 В) → AMS1117
(5→3.3 В) работает всегда. Сон сделан программно: когда ACC гаснет, блок
перестаёт отправлять кадры, ждёт `IGNITION_OFF_TO_SLEEP_S` (20 с) и уходит
в глубокий сон; просыпается по тому же входу ACC.

**Ограничение ESP32:** просыпаться из глубокого сна он умеет только по выводам
RTC — `GPIO 32…39`. Значит **ACC надо сажать на один из входов `DIN_1…DIN_6`**
(GPIO36, 39, 34, 35, 32, 33). Если ACC окажется на другом входе, блок будет
молчать, но в сон не уйдёт — в логе будет предупреждение.

После просыпания модуль перезапускается, и приборка видит это как перезапуск
блока (кадр `0x7F0`) — так и задумано протоколом.

Сон включается сам, как только в таблице проводов появится строка
`SIG_IGNITION`. Пока её нет, блок работает всегда — это безопасно.

## GPS и навигация: почему GPS нужен, а навигация работает и без него

Это два разных вопроса, и их легко перепутать.

**Карта работает без GPS.** В режиме навигации приборка поднимает WebView и
грузит карту OpenStreetMap из интернета (`Dashboard/MapWebView.qml`). Ей нужен
только доступ в сеть — ни GPS, ни ESP32 для этого не требуются.

**А вот отметка машины на карте без GPS не появится.** Спутникового приёмника
у плат RK3588 нет, и «взять координаты» приборке неоткуда. Сейчас карта вообще
открывается на фиксированном прямоугольнике (координаты зашиты в `mapUrl`),
то есть это не навигация, а картинка.

Значит GPS-модуль на плате блока сбора — единственный источник координат
в системе, и выбрасывать его нельзя. Чтобы координаты дошли до приборки,
нужно три вещи:

1. разбор NMEA в прошивке (модуль отдаёт строки `$GPRMC`/`$GPGGA` по UART0);
2. **протокол 1.3**: новый кадр с положением (широта, долгота, курс, скорость,
   точность, признак «есть фикс») — в 1.2 такого кадра нет;
3. на приборке — приём кадра и передача координат в карту (сейчас страница
   карты статичная, её надо научить следовать за машиной).

Тот же GPS даёт точное время — это второй кандидат в кадр: часы приборки
сейчас берут системное время платы, у которой нет батарейки RTC.

## Открытые вопросы (нужны решения владельца)

1. **Список проводов старой приборки**: контакт → сигнал → как работает
   электрически. Без него таблица остаётся пустой.
2. **Какая машина и какой ЭБУ** (модель, год, код двигателя, номер блока) и
   чем вы её сейчас диагностируете (VCDS / Ваг-Ком / ELM327). По этому
   определится протокол K-линии: KWP1281, KWP2000 или OBD-II по K-линии.
3. **Список блоков измерений, которые нужны с ЭБУ**: температура, расход,
   напряжение, короткая и длинная коррекции — их надо будет найти в дампе.
4. **Расширять ли протокол до 1.3** (кадр с координатами GPS и временем) —
   без этого навигация останется статичной картинкой.
5. **Чем питается сама приборка** (RK3588): от ACC или постоянно? Если
   постоянно — она будет показывать «НЕТ ДАННЫХ CAN» на стоянке, когда блок
   уснёт; это решается либо питанием приборки от ACC, либо отдельным кадром
   «блок уходит в сон».
6. Чем питаются датчики топлива/температуры: одиночный провод (реостат
   на массу) или на проводе есть стабилизированное напряжение (п. 3).
