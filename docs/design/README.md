# Референсы дизайна

Скриншоты, которые присылает заказчик по ходу обсуждения внешнего вида.
Это именно превью для обсуждения, а не исходники для сборки: для реализации
нужны макет в 1920×720 и активы (SVG/PNG) от дизайнера.

| Файл | Что это |
|---|---|
| `genesis.jpg` | Эскиз нового скина (800×600, JPG): тёмный сине-чёрный фон, два круглых прибора слева/справа, центральная колонка с данными, широкая светлая полоса внизу. Использовать как ориентир по настроению/палитре, не как источник размеров. |
| `climate.png` | Референс климатического виджета (см. задачу по климату, режим 6 центральной панели). |
| `ipsum_flying_wheel.png` | Скрин бага «колесо летает вокруг машины» (пивот Wheel_FR был в 1.18 м от меша; исправлено сдвигом меша в GLB). |

## Интерфейс мультимедиа (Android)

Требования к макетам, активам и состояниям — `docs/design_brief.md`.
Коротко: макет в точном разрешении экрана (ориентир 1920×1080), активы
слоями (SVG-иконки, PNG-фоны, без вклеенного текста), все состояния включая
**фокус для джойстика**, палитра и типографика токенами, ночная тема,
схема обхода джойстиком. Референс стиля климата — `climate.png`.

## Статус

Дизайнер рисует новый скин **по `genesis.jpg`**, обещал закончить примерно
через неделю (ориентир — начало ноября 2026). До этого арт не трогаем.

## Когда дизайнер отдаст скин — запросить

1. Макет **1920×720** и отдельно центральную зону (492×404).
2. **Циферблаты** двух приборов — SVG (или PNG 2×), пустые: без стрелок
   и без встроенных цифр, если они будут отдельными.
3. **Стрелку + размытый шлейф** отдельными файлами, в одной позе и на одном
   холсте (720×720, как `needls_*.svg`) — см. `docs/needle_trail.md`.
4. **Иконки ламп/значков** — монохромные белые SVG (цвет зададим в QML).
5. Палитру (точные HEX: фон, акценты) и шрифт (с кириллицей, если подписи
   на русском — Kdam Thmor Pro без неё).

План реализации по новому скину: заменить арт в `Dashboard/Gauge.qml`
(циферблат, стрелка, иконки), шлейф сделать по `docs/needle_trail.md`,
центр — по макету; подробности обсуждаются в переписке.

## Чек-лист для финальной 3D-модели (когда приедет от дизайнера)

Сейчас в проекте стоит `Dashboard/assets/ipsum_3D.glb` — временная, с
двумя ручными правками (см. `PROJECT_STATE.md`). Для финальной модели
важно:

1. **Единицы/масштаб** — любые, но скажите какие (сейчас метры, машина
   ~1.9 м; масштаб в сцене — `scene.carEnlarge`).
2. **Имена узлов** — сохранить осмысленные (`Wheel_FL/FR/RL/RR`,
   `Door_FL/FR/RL/RR`, `Door_5` — багажник, `Capot`, `Car_body`). В QML
   имена glTF не пробрасываются, поэтому роли назначаются по порядку —
   сохранение порядка и имён сильно упрощает жизнь.
3. **Пивоты** (главное!):
   - колёса — ровно в центре ступицы (иначе колесо «летает вокруг
     машины»: так было с `Wheel_FR`, его меш оказался в 1.18 м от узла);
   - двери/капот/багажник — на петлях (петля двери — вертикальная ось
     у передней кромки; капот — задняя верхняя кромка; 5-я дверь — верх).
4. **Ось вращения колёс** — локальная z (диск колеса лежит в x-y).
   Если в финальной модели оси другие — скажите, поправим в сцене.
5. **Текстуры** — желательно запечённые (один материал/атлас), как сейчас.
6. **Анимации** — не нужны: всё (колёса, двери, капот, подвеска) делаем
   в QML через узлы.
