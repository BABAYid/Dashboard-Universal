# Бриф дизайнеру: интерфейс мультимедиа (Android)

Что нужно получить от дизайнера, чтобы интерфейс можно было собрать, а не
подбирать пиксели наугад. Тот же документ — наш чек-лист приёмки.

Сперва о технике, потому что от неё зависит формат сдачи.

---

## 1. На чём это будет собрано (и почему это важно дизайнеру)

Мультимедиа — Android. Мост (чтение уведомлений навигатора, снятие экрана,
медиа-сессия, mock location) пишется нативным кодом (Kotlin), поэтому
**интерфейс делаем там же — Kotlin + Jetpack Compose**, одним приложением.

Что это значит для дизайна:

- интерфейс — **живой**: все цифры и тексты приходят из данных, ни один экран
  не «нарисованная картинка»;
- у каждого элемента есть **состояния** (нажато, неактивно, выбрано,
  в фокусе), и их надо нарисовать;
- активы отдаются **слоями** (иконка отдельно, фон отдельно, плашка отдельно),
  а не одним PNG с уже вклеенным текстом;
- шрифты и цвета задаются **токенами** (один фон, один акцент, один
  предупреждающий), чтобы мы подключили их темой, а не искали HEX в пикселях.

---

## 2. Что нужно сдать

### 2.1 Разрешение и сетка

- Макеты в **точном разрешении экрана**. Ориентир — **1920×1080** (панель
  13.3–15.6″); если финальная панель другая, разрешение фиксируем ДО начала
  рисования и меняем только его.
- Сетка 8 px (отступы 8/16/24/32), безопасные поля от краёв 24 px.
- Отдельно — макет в **портретной ориентации не нужен**: интерфейс
  горизонтальный, фиксированный.

### 2.2 Экраны (список минимальный, можно объединять по смыслу)

| Экран | Что на нём |
|---|---|
| **Главный (лаунчер)** | плитки/список: навигация, медиа, климат, камера, телефон, настройки |
| **Навигация** | карта на весь экран + плашка следующего манёвра + поиск/адрес + избранное (дом/работа) |
| **Медиа** | радио/трек/исполнитель, прогресс, кнопки, список станций/плейлистов |
| **Климат** | уставка, вентилятор, поток воздуха, AC/AUTO/рециркуляция/обдув, температуры салона и испарителя — плюс состояние «нет данных» |
| **Настройки** | темы, яркость, звук, источник GPS, диагностика связи |
| **Камера** (если будет) | картинка + разметка траектории |

Референс по стилю климата — `docs/design/climate.png`: брать настроение,
палитру и компоновку, но **не** копировать пиксель в пиксель — это референс.

### 2.3 Состояния — обязательны все

Для каждой интерактивной штуки:

| Состояние | Зачем |
|---|---|
| обычное | база |
| нажатое | отклик на тач |
| **в фокусе** | джойстик листает элементы — рамка/подсветка должна быть видна, но не кричать |
| неактивное | например, «климат недоступен» |
| выбранное | активная станция, включённый AC |
| «нет данных» | цифры не пришли — показываем `—`, а не `0` |

Без состояния фокуса интерфейс с джойстика будет неуправляем — это первое,
что мы проверим на приёмке.

### 2.4 Активы: формат и правила

| Что | Формат | Требования |
|---|---|---|
| Иконки, значки | **SVG** (вектор) или PNG @3× | монохромные, если цвет задаётся темой; называть по смыслу (`ic_climate_fan.svg`) |
| Фоны, градиенты, текстуры | PNG (при необходимости) | без текста и без вклеенных элементов |
| Иллюстрации (машина, схемы) | PNG @2×–@3× с прозрачностью | отдельные файлы |
| Логотипы производителей | PNG с прозрачностью | по требованию правообладателей |
| Шрифты | TTF/OTF **с кириллицей и лицензией** | указать семейство, начертания и где брать (бесплатные Google Fonts — ок) |

Обязательно: **никакого текста, «вклеенного» в картинку** — все надписи мы
рисуем кодом, иначе они не переведутся и не переразрядятся.

### 2.5 Токены оформления

Отдельным небольшим списком, как таблица:

- палитра: фон, поверхность, поверхность-2, акцент, акцент-2, успех,
  предупреждение, опасность, текст, текст-второстепенный (HEX);
- типографика: стили (заголовок, значение, подпись) — размер, начертание,
  межстрочный;
- скругления и тени: значения в px;
- **ночная тема**: это машина, ночью яркий экран слепит. Нужны дневная и
  ночная палитры (или правило переключения).

### 2.6 Анимации

Список с параметрами (длительность, кривая): появление панелей, переключение
экранов, нажатие, прогресс загрузки. Сложное (например, анимированный
индикатор спутников) — отдать как **Lottie JSON** с указанием, что
показывать при 0 спутников.

### 2.7 Поведение и фокус

Короткая схема для каждого экрана: **порядок обхода джойстиком** (что
выбирается первым, куда ведёт «вверх/вниз/влево/вправо»), и что делает
кнопка BACK (выход куда?). Проще всего нарисовать стрелками поверх макета.

### 2.8 Чего не нужно

- Мокапы «как будет выглядеть» без слоёв — по ним нельзя собрать интерфейс.
- Скриншоты системных диалогов Android.
- Иконки в формате многослойного PSD (нужен SVG/PNG).
- Заглушки вместо шрифта из дефолтной системы: шрифт выбирается один раз и
  сдаётся файлом.

## 3. Как сдавать работу

1. **Figma** (или аналог) с компонентами и вариантами состояний — мы видим
   структуру, а не одну картинку.
2. **Экспорт активов** в папку по правилам: `assets/icons/`, `assets/bg/`,
   `assets/fonts/` — с именами по смыслу.
3. **Документ-спека** (страница в Figma или Markdown): палитра, типографика,
   состояния, фокус, анимации.
4. Финальная проверка: макет 1920×1080 на экране, покрутить в фокусе и увидеть,
   что стрелки джойстика не «прыгают» по экрану хаотично.

---

## 4. Как это ляжет в код (чтобы дизайнер понимал контекст)

- Цвета → тема Compose (`ColorScheme`), тексты → стили, иконки → `drawable`.
- Раскладка в Compose — flex-подобная: дизайн лучше рисовать на сетке, а не
  «на глаз», иначе на другом разрешении поедет.
- Динамические значения (температура, скорость, название трека) дизайнер
  показывает **плейсхолдером с примером** и, если важен, ограничением длины
  («название трека в одну строку, обрезка с многоточием»).
- Климат берёт данные из контракта сети: уставка, вентилятор 0…7, режим
  потока (`face`, `feet`, `face_feet`, `auto`), AC/AUTO/рециркуляция/обдув,
  температуры. Если цифры нет — в макете это состояние «—», а не ноль.

---

## 5. Приёмка: наши критерии

| Критерий | Проверка |
|---|---|
| Разрешение | файл ровно 1920×1080 (или согласованное) |
| Слои | иконки отдельно от фонов, текста в картинках нет |
| Состояния | есть фокус, нажатие, выбранное, неактивное, «нет данных» |
| Токены | палитра и типографика отдельным списком, ночная тема есть |
| Шрифт | файл с кириллицей и лицензией |
| Фокус | схема обхода джойстиком по каждому экрану |
| Анимации | параметры или Lottie |
