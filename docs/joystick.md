# Джойстик BMW iDrive — управление приборкой без тачскрина

У панели Tianma нет сенсорного экрана, а в машине нет мыши: почти весь
интерфейс приборки (режимы центральной панели, навигация, настройки, одометр)
управляется физическим вводом. Ввод приходит от джойстика BMW iDrive
(F-серия), закреплённого в тоннеле рядом с рычагом АКПП, через отдельный ESP32
и кадр CAN `0x530`.

```
 Джойстик BMW ──CAN 500 ──► ESP32 ввода ──CAN 500──► RK3588 ──► QML
   (0x267/0x264)        (пробуждение,          (0x530:               (слой фокуса)
                         heartbeat, разбор)     кнопки и энкодер)
```

## Почему отдельный ESP32

В тоннеле уже стоит ESP32 селектора АКПП (проект `AKPP_Selector`), который
управляет коробкой: моторчик, концевики, блокировки по тормозу и скорости.
Джойстик — не критичный модуль, и вешать его на контроллер коробки значит
связать два релиза и две причины отказа. Поэтому у ввода своей ESP32:
прошивка — `firmware/joystick/`, шина для событий — приборная.

## Протокол BMW-джойстика

Найдено [здесь](https://www.drive2.ru/l/715135008162987383/), проверено на
BMW F20. Скорость 500 кбит/с, стандартные 11-битные кадры, 8 байт.

Джойстик без CAN «мёртв»: ему нужны пробуждение и регулярный heartbeat.

**От нас джойстику:**

| ID | Данные | Когда |
|---|---|---|
| `0x202` | `FD` | подсветка; отправлять **дважды** (модуль требует повтора) |
| `0x563` | `63` | heartbeat, каждые 100 мс, постоянно |
| `0x273` | `1D E1 00 F0 FF 7F DE 00` | пробуждение при старте; повтор, если 2 с нет событий |

**От джойстика:**

`0x267` — события. `E1 FD [счётчик] [состояние] [модификатор] [указатель]`

- модификатор `0xC0` — кнопка: указатель `0x01` MENU, `0x02` BACK,
  `0x04` OPTION, `0x08` RADIO, `0x10` MEDIA, `0x20` NAV, `0x40` TEL;
  состояние `0x01` нажата, `0x00` отпущена;
- модификатор `0xDD` — направление: `0x11` вперёд, `0x41` назад,
  `0x21` вправо, `0x81` влево;
- модификатор `0xDE` — нажатие джойстика.

`0x264` — энкодер. `E1 FD [счётчик] [младший] [старший] 1E`, значение
счётчика 16-битное; ESP32 публикует знаковую разность между соседними
значениями.

`0x5E7` — подтверждение событий, игнорируется.

## Кадр 0x530 на приборной шине

Подробно — в `can_protocol_v1.5.txt`, раздел «ID: 0x530». Кратко:

| Байт | Что |
|---|---|
| 0 | вид: `0x01` кнопка, `0x02` энкодер |
| 1 | код кнопки: 1 MENU, 2 BACK, 3 OPTION, 4 RADIO, 5 MEDIA, 6 NAV, 7 TEL, 8 UP, 9 DOWN, 10 LEFT, 11 RIGHT, 12 PRESS |
| 2 | кнопка: `0x01` нажата / `0x00` отпущена; энкодер: знаковая дельта int8 |
| 3 | счётчик событий, mod 256 |
| 4–7 | резерв, 0 |

## Что делает каждая кнопка в приборке

Таблица одна на всё: код из протокола → имя действия (`InputController.qml`),
что делает действие (`Main.qml`, функция `applyInput`).

| Кнопка | Действие |
|---|---|
| NAV | войти в навигацию / выйти назад |
| BACK | закрыть настройки, выйти из навигации |
| MEDIA | медиа-режим центральной панели (7) |
| RADIO | медиа-режим (радио — часть медиа) |
| OPTION / MENU | открыть настройки; повторное — закрыть без сохранения |
| ← / → | листать режимы центральной панели |
| PRESS (нажатие) | следующий режим центральной панели |
| энкодер | листать показания одометра: ODO → TRIP A → TRIP B |
| TEL, UP, DOWN | зарезервировано (зум карты, листание списков) |

Пока открыт оверлей настроек, ввод уходит ему: закрыть можно BACK/OPTION/MENU,
остальное гасится, чтобы не переключать режим «под» оверлеем.

## Эмулятор на столе

Работает через тот же `InputController`, то есть проверяется настоящий код,
а не отдельная демо-ветка:

| Клавиша | Кнопка |
|---|---|
| F1 / F2 / F3 | MENU / BACK / OPTION |
| F4 / F5 / F6 | RADIO / MEDIA / NAV |
| F7 | TEL |
| F9 / F10 / F11 / F12 | UP / DOWN / LEFT / RIGHT |
| Insert | PRESS |
| `=` или `+` | энкодер вперёд |
| `-` или `_` | энкодер назад |

Есть и скриптованный проигрыш из командной строки — он собирает настоящие
кадры `0x530` и подаёт их в `CanBackend::feedFrame`:

```bash
DASHBOARD_INPUT_DEMO="nav,90,right,40,press,30,back" ./build/appDashboard --mock
```

Формат: имена действий через запятую; число после имени — пауза до
следующего события в 100 мс. Имена: `nav`, `back`, `media`, `radio`, `menu`,
`option`, `up`, `down`, `left`, `right`, `press`, `next`, `prev`.

## Проверка на машине

```bash
sudo ip link set can0 up type can bitrate 500000
candump can0          # видеть 0x530 в момент нажатий
```

Если `0x530` нет, а джойстик светится — проверять ESP32 ввода (heartbeat
`0x563` каждые 100 мс и пробуждение `0x273`), а не приборку: без этого
модуль не отвечает вообще.
