# Автономная навигация в приборке (офлайн)

Цель: полноценная навигация **на самой приборке**, без Android и без
интернета: карта, маршрут, подсказки, позиция от USB-приёмника.

Документ фиксирует решения и порядок работ. Статус: **17.11.2026** —
карта и маршруты собираются **по областям**: Московская область и
Санкт-Петербург (с Ленобластью) отдельными файлами тайлов, маршруты — одним
графом на склейке Центрального и Северо-Западного ФО. Покрытие расширяется
добавлением новой области, без пересборки остальных (см. «Данные: области
карты» и `tools/nav-build-tiles-area.sh`).

## Что имеем

- Экран приборки 1920×720, тачскрина нет — ввод только джойстиком или с
  телефона по сети.
- USB GPS на приборке (u-blox M10, 10 Гц) — выбран, ждём.
- Второй приёмник будет на мультимедиа — это отдельный блок, к приборке
  отношения не имеет.

## Данные: области карты

Карта собирается **по областям**: у каждой свой MBTiles, а `tile-server.py`
принимает несколько файлов и отдаёт тайл из первого, где он есть. Так можно
расширять покрытие по одной области.

| Область | bbox (lon,lat) | Файл тайлов | z | Тайлов | Размер |
|---|---|---|---|---|---|
| Московская область | 34.8,54.1 … 40.4,57.1 | `maps/tiles-mosobl.mbtiles` | 8–15 | 328 529 | 792 МБ |
| Санкт-Петербург + Ленобласть | 28.0,58.4 … 31.8,61.0 | `maps/tiles-spb.mbtiles` | 8–15 | 217 040 | 315 МБ |

Собрано 17.11.2026 `tools/nav-build-tiles-area.sh` (Planetiler с `--bounds`:
обрезать выгрузку заранее не нужно — Planetiler сам отбрасывает всё вне bbox).

**Маршруты** — GraphHopper на склеенной выгрузке `maps/routes.osm.pbf`
(Центральный ФО + Северо-Западный ФО: Москва и область, Петербург и
Ленобласть, плюс остальные области этих округов). Склейка —
`tools/nav-union.py`, потому что GraphHopper читает ровно один
`datareader.file`. Граф пересоберётся сам при первом запуске
`tools/nav-route.sh` в `maps/graph-cache` (старый кэш перед сменой данных
надо убрать — он привязан к исходному файлу).

**База адресов** (`maps/addresses.sqlite`, поиск для приборки) строится
`tools/nav-search.py build` из того же `maps/routes.osm.pbf`.

### Грабли сборки данных (17.11.2026 — стоили нескольких прогонов)

1. **osmium вместо pyosmium.** Склейка 124 млн узлов на pyosmium шла 40 минут
   и падала; `osmium` (C++) делает то же за минуту. Ставится без root:
   `./tools/osmium-bootstrap.sh` (пакет `osmium-tool` распаковывается в
   `build/osmium-tool`, система не затрагивается).
2. **Порядок элементов в PBF важен.** GraphHopper требует «все узлы → все
   пути → все отношения». Склейка «файл за файлом» даёт невалидный файл
   (`way elements must be located before relation elements`); `osmium merge`
   раскладывает элементы правильно.
3. **У соседних округов есть общие узлы.** У границы Твери и Новгорода пути
   заходят в оба экстракта, и на них `osmium merge` падает с
   `Possibly duplicate OSM node ID`. Лечится обрезкой области по bbox
   (`tools/nav-extract.sh`) перед склейкой — так и сделано для Питера
   (bbox 28.0,58.4 … 31.8,61.0, файл `maps/spb.osm.pbf`, 149 МБ).
4. **Обрезка на pyosmium была сломана** (и сохранена как резервный путь,
   `tools/nav-clip.py`): она складывала пути в список и писала после прохода,
   а pyosmium отдаёт временные объекты — на выходе были миллионы узлов и ноль
   путей. Плюс id узлов в множестве Python съедали гигабайт и процесс убивало
   по памяти. Теперь пишет потоком, id хранит в numpy.

### Что проверено на собранных данных (17.11.2026)

| Маршрут по Петербургу | 59.9390,30.3158 → 59.9550,30.3000 = 2859 м, 9 манёвров |

### Как добавить ещё одну область

```bash
cd "/home/oleg/Документы/новая приборка"
# 1) выгрузка округа (Geofabrik)
./tools/nav-fetch.sh nwfed            # или свой URL в maps/<имя>.osm.pbf
# 2) тайлы области (20–40 минут)
./tools/nav-build-tiles-area.sh spb maps/nw-fed.osm.pbf 28.0,58.4,31.8,61.0
# 3) маршруты: добавить выгрузку в склейку и пересобрать граф
PYTHONPATH=build/pylibs python3 tools/nav-union.py \
    maps/routes.osm.pbf maps/district.osm.pbf maps/nw-fed.osm.pbf
rm -rf maps/graph-cache && ./tools/nav-route.sh
```

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Приёмник | `gpsd` (TCP 2947, JSON) | разбирает NMEA, держит фикс, настраивает частоту; есть на любой плате |
| Тайлы | **Planetiler** → MBTiles (z8…15) | собрано 13.11.2026: 448 МБ на весь bbox «Москва + 100 км» |
| Рисование карты | MapLibre GL JS в `WebView` | умеет локальные тайлы, маршрут линией, поворот по курсу; Qt-рендерер вектора писать не надо |
| Сервер тайлов | уже есть `QHttpServer` (порт 8080) | отдаёт `/tiles/{z}/{x}/{y}` из MBTiles (пока — прототип `tile-server.py` на :8090) |
| Маршруты | **GraphHopper 9.1** (Java, офлайн) | в коде уже GraphHopper: `build/gh/config.yml`, порт 8989, граф в `maps/graph-cache`; даёт геометрию, инструкции и ETA. Valhalla — запасной вариант, если GraphHopper не хватит |
| Поиск адреса | этап 2: SQLite FTS по `addr:*` из выгрузки | компактно (~100 МБ), без сервера; Nominatim/Photon — если качества не хватит |

Суммарно на диске: тайлы 0.45 ГБ + граф маршрутов 0.4 ГБ + данные поиска
~0.1 ГБ. Для платы с 100+ ГБ это нормально.

## Пайплайн подготовки данных (на ПК, один раз)

1. Выгрузка OSM под наш bbox: BBBike (свой прямоугольник) или Geofabrik.
   Файл `.osm.pbf`, ожидаемо 1–2 ГБ.
2. Тайлы: `tools/nav-build-tiles.sh` (Planetiler, z8…15).
3. Маршруты: GraphHopper сам строит граф из `maps/district.osm.pbf`
   в `maps/graph-cache` при первом запуске `tools/nav-route.sh`
   (конфиг — `build/gh/config.yml`, профиль `car`).
4. Результат копируется на плату в `/opt/dashboard/maps/`.

Скрипты положим в `tools/nav/` — по мере готовности.

## Готовые скрипты (в проекте)

| Скрипт | Что делает |
|---|---|
| `tools/nav-fetch.sh moscow\|district` | качает выгрузку OSM в `maps/` (BBBike для города, Geofabrik для округа) |
| `tools/nav-clip.py` | режет выгрузку по bbox на pyosmium (замена `osmium extract`); id хранятся в numpy — память не растёт с размером выгрузки |
| `tools/nav-build-tiles.sh` | первая сборка: `maps/tiles.mbtiles` («Москва + 100 км») из `maps/district.osm.pbf` |

| `tools/nav-union.sh` | склеивает выгрузки в один PBF для GraphHopper (`maps/routes.osm.pbf`) через `osmium merge` |
| `tools/nav-extract.sh` | обрезка области через `osmium extract` (C++, минута на сотни МБ) |
| `tools/osmium-bootstrap.sh` | ставит `osmium` (CLI) без root: `apt-get download` + `dpkg -x` в `build/osmium-tool` |
| `tools/tile-server.py` | отдаёт `/tiles/…`, `/style.json`, `/map.html` из `Dashboard/map/`; логирует пустые тайлы |
| `tools/nav-serve.sh` | запускает сервер тайлов на :8090 и открывает карту в браузере |
| `tools/nav-route.sh` | запускает GraphHopper на :8989 (граф — `maps/graph-cache`, конфиг — `build/gh/config.yml`) |
| `tools/gps_test_server.py` | тестовый gpsd: JSON по TCP 2947, 10 Гц, демо-трек по Москве (пока нет USB-приёмника) |

| `tools/load_test.sh` | сценарий нагрузки на столе: смена экранов, шторм WS, churn маршрутов, потеря GPS, метрики |

## Слои приборки

1. `GpsBackend` (C++, готов 13.11.2026): подписка на `gpsd` (TCP 2947,
   JSON TPV/SKY) — позиция, курс, скорость, спутники, hdop; отдаёт в QML
   (карта, камеры) и в сетевой слой — `car.gps` с `valid`/`age_ms` (контракт
   `docs/integration.md`). Устаревание >5 с → `valid = false`.
   Без приёмника тестируется `tools/gps_test_server.py` (тот же протокол
   по TCP); при появлении u-blox M10 — просто `gpsd -n /dev/ttyUSB0`.
2. `MapView` (QML + WebView): MapLibre, стиль под палитру приборки, маркер
   машины со стрелкой курса, режим «карта по курсу»; зум — джойстиком
   ▲/▼ в навигации (z8…15, по умолчанию 14). Здания — слой `building`
   (z14+), подписи улиц — `transportation_name` с SDF-глифами Lato.
3. `RouteService` (QML): запрос к GraphHopper, хранение активного маршрута,
   линия на карте, подсказки (манёвр, расстояние, улица, ETA); принимает
   маршрут и от Android (`route_handoff`, см. ниже).
4. `NavPanel` (уже есть): плашка манёвра и карточка без карты — остаются
   для Android-режима. Для своей карты — `RouteHint.qml`: внизу по центру
   стрелка манёвра, «ЧЕРЕЗ N М», текст подсказки и остаток пути
   (RouteService/GraphHopper, значения обновляются по мере движения).

## Ввод адреса без тачскрина

| Способ | Как работает |
|---|---|
| Избранное | «Дом», «Работа», «АЗС», «Мойка» — энкодер листает список, PRESS строит маршрут (13.11.2026) |
| Недавние | последние 10 маршрутов, сохраняются между запусками (C++/QSettings, `Dashboard/nav/RecentDestinations`) (13.11.2026) |
| По карте | ◀/▶ сдвигают вид, в центре перекрестие; PRESS = «сюда» (13.11.2026) |
| С телефона | `{"type":"address","text":"…"}` по WebSocket (`/ws`) → поиск в SQLite FTS → маршрут (13.11.2026) |
| Маршрут целиком от Android | `{"type":"route_handoff","lat":..,"lon":..}` — приборка строит сама и отдаёт `route_state` раз в секунду; `route_clear` отменяет. Кадры экрана — только резерв. См. `docs/priberka_route_handoff.md` |

Управление в навигации (джойстик): ▲/▼ — зум (z8–15), ◀/▶ — сдвиг вида
(появляется перекрестие), энкодер — листать избранное+недавние, PRESS —
маршрут к выбранному пункту или к перекрестию, BACK/NAV — выход.
После выбора пункта назначения камера плавно перелетает к точке
(`map.flyTo`, ~1.5 с) и так же возвращается к машине.

Поиск адреса — `tools/nav-search.py`: строит `maps/addresses.sqlite`
(SQLite FTS5: дома, улицы, города, парки и площади из `district.osm.pbf`,
дополненные названиями из готовых тайлов). Сборка из pbf занимает ~40-50
минут (как и тайлы), затем `tiles` дописывает названия из `tiles.mbtiles`
за пару минут — в итоге ~2.6 млн записей, ~300 МБ.

    python3 tools/nav-search.py build maps/district.osm.pbf maps/addresses.sqlite
    python3 tools/nav-search.py tiles  maps/addresses.sqlite maps/tiles.mbtiles

Проверка с телефона (приборка запущена): `python3 tools/send_address.py "Красная площадь"`.
Проверка route_handoff: `python3 tools/send_route_handoff.py --lat 55.770 --lon 37.640 --name "Тест" --listen 4`
(или `--clear`); всё на столе поднимает `./tools/desk_demo.sh`.

`tools/tile-server.py` отдаёт поиск по `/search?q=…&lat=&lon=&limit=5`
(с позицией — ближайшие первые, без неё — по релевантности FTS).
База — в `maps/` (в git не попадает).

Полноценный ввод текста джойстиком — не делаем: это сотни щелчков.
Формулировка в интерфейсе: «выберите на карте или с телефона».

## Открытые вопросы

1. MapLibre в WebView устроит по производительности на новой плате
   (Radxa Q6A / Qualcomm + Adreno) — проверить на железе; запасной вариант —
   свой QML-рендер векторных тайлов (дороже в разработке).
2. Нужны ли пробки / слои POI — нет, офлайн их не будет.
3. Хранить Valhalla на плате или на мультимедиа (там 8 ГБ памяти)?
   Логично на приборке: навигация должна работать, даже если Android выключен.
4. Как обновлять карты: `./tools/nav-update.sh` — одна команда
   (выгрузка OSM → тайлы → граф GraphHopper → база адресов, 1.5–2 часа на
   ПК), затем перезапустить серверы. Решено 17.11.2026.

## Инструмент сборки тайлов: Planetiler (вместо tilemaker)

13.11.2026: tilemaker 2.4.0 не собрался на текущем тулчейне — `Boost::system`
стал header-only, rapidjson 1.1.0 не компилируется GCC 15, с master-rapidjson
вылезает конфликт `namespace boost::sort` с Boost 1.90. Патчить не стали.

Берём **Planetiler** (Java, без сборки, тот же `.mbtiles`):

```bash
# нужен JDK 21: build/toolchain/jdk21
build/toolchain/jdk21/bin/java -Xmx3g -jar build/toolchain/planetiler.jar \
  --osm-path=maps/district.osm.pbf --output=maps/tiles.mbtiles \
  --bounds=36.016,54.855,39.218,56.657 --minzoom=8 --maxzoom=15 \
  --download --force --tmpdir=build/tmp --download_dir=build/toolchain/sources
```

## Решено 13.11.2026: пустая подложка карты

Что было видно: маршрут и CSS-маркер машины рисуются, а подложка (вода,
дороги, здания) — пустой фон. В браузере `map.html` при этом рисовалась.
Причин оказалось **две**, и обе в WebView приложения, а не в тайлах.

**Причина 1 — WebGL заблокирован.** Chromium в QtWebEngine по умолчанию
блокирует WebGL на программном рендерере (llvmpipe/Mesa):
`ContextResult::kFatalFailure: WebGL1 blocklisted`, и MapLibre падает с
`Failed to initialize WebGL` ещё в конструкторе — карта вообще не создаётся,
остаётся только CSS-маркер. В браузере WebGL есть, поэтому там всё
рисовалось.
Фикс: `main.cpp` при старте выставляет
`QTWEBENGINE_CHROMIUM_FLAGS=--ignore-gpu-blocklist` (если флаг ещё не
задан — дописывает, не затирая). Сделано в `main.cpp`, а не в `run.sh`,
потому что на плате приборка стартует из systemd (`deploy/systemd/
dashboard.service`), где `run.sh` не участвует. Проверено: в app-логе
`webgl1: true`, карта создаётся.

**Причина 2 — MapLibre не резолвит относительный URL тайлов.** В
`style.json` было `"tiles": ["/tiles/{z}/{x}/{y}"]`. MapLibre v4.7.1
передаёт этот URL в воркер как есть, и `new Request('/tiles/…')` в воркере
падает: `Failed to parse URL from /tiles/…`; запросы тайлов не уходят
вообще (0 запросов к серверу). Причина — в самом MapLibre: в контексте
воркера `Request` требует абсолютный URL. Карта в браузере рисовалась
на версии с абсолютным адресом тайлов; свежую (относительную) версию в
браузере не перепроверяли, но WebView падал именно из-за этого.
Фикс: в `Dashboard/map/index.html` в конструктор карты добавлен
`transformRequest`, который абсолютизирует любой относительный URL от
`document.baseURI`. Так работает и в браузере, и в WebView, и не зависит
от порта/адреса сервера — `style.json` остался портативным.

Проверено 13.11.2026:
