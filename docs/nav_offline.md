# Автономная навигация в приборке (офлайн)

Цель: полноценная навигация **на самой приборке**, без Android и без
интернета: карта, маршрут, подсказки, позиция от USB-приёмника.

Документ фиксирует решения и порядок работ. Статус: **13.11.2026 — идёт
работа**. Скрипты пайплайна готовы, тайлы собраны на весь bbox
«Москва + 100 км» (448 МБ, z8–15), карта в приложении рисует подложку
(раздел «Пустая подложка…»); ждём USB GPS-приёмник, дальше — маршруты
и поиск адреса.

## Что имеем

- Экран приборки 1920×720, тачскрина нет — ввод только джойстиком или с
  телефона по сети.
- USB GPS на приборке (u-blox M10, 10 Гц) — выбран, ждём.
- Второй приёмник будет на мультимедиа — это отдельный блок, к приборке
  отношения не имеет.

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Приёмник | `gpsd` (TCP 2947, JSON) | разбирает NMEA, держит фикс, настраивает частоту; есть на любой плате |
| Тайлы | **Planetiler** → MBTiles (z8…15) | собрано 13.11.2026: 448 МБ на весь bbox «Москва + 100 км» |
| Рисование карты | MapLibre GL JS в `WebView` | умеет локальные тайлы, маршрут линией, поворот по курсу; Qt-рендерер вектора писать не надо |
| Сервер тайлов | уже есть `QHttpServer` (порт 8080) | отдаёт `/tiles/{z}/{x}/{y}` из MBTiles (пока — прототип `tile-server.py` на :8090) |
| Маршруты | **GraphHopper 9.1** (Java, офлайн) | в коде уже GraphHopper: `build/gh/config.yml`, порт 8989, граф в `maps/graph-cache`; даёт геометрию, инструкции и ETA. Valhalla — запасной вариант, если GraphHopper не хватит |
| Поиск адреса | этап 2: SQLite FTS по `addr:*` из выгрузки | компактно (~100 МБ), без сервера; Nominatim/Photon — если качества не хватит |

Суммарно на диске: тайлы 0.45 ГБ + граф маршрутов 0.4 ГБ + данные поиска
~0.1 ГБ. Для платы с 100+ ГБ это нормально.

## Пайплайн подготовки данных (на ПК, один раз)

1. Выгрузка OSM под наш bbox: BBBike (свой прямоугольник) или Geofabrik.
   Файл `.osm.pbf`, ожидаемо 1–2 ГБ.
2. Тайлы: `tools/nav-build-tiles.sh` (Planetiler, z8…15).
3. Маршруты: GraphHopper сам строит граф из `maps/district.osm.pbf`
   в `maps/graph-cache` при первом запуске `tools/nav-route.sh`
   (конфиг — `build/gh/config.yml`, профиль `car`).
4. Результат копируется на плату в `/opt/dashboard/maps/`.

Скрипты положим в `tools/nav/` — по мере готовности.

## Готовые скрипты (в проекте)

| Скрипт | Что делает |
|---|---|
| `tools/nav-fetch.sh moscow\|district` | качает выгрузку OSM в `maps/` (BBBike для города, Geofabrik для округа) |
| `tools/nav-clip.py` | режет выгрузку по нашему bbox на pyosmium (замена `osmium extract`, ставится без root) |
| `tools/nav-build-tiles.sh` | собирает `maps/tiles.mbtiles` из `maps/district.osm.pbf` через Planetiler (10–20 минут) |
| `tools/tile-server.py` | отдаёт `/tiles/…`, `/style.json`, `/map.html` из `Dashboard/map/`; логирует пустые тайлы |
| `tools/nav-serve.sh` | запускает сервер тайлов на :8090 и открывает карту в браузере |
| `tools/nav-route.sh` | запускает GraphHopper на :8989 (граф — `maps/graph-cache`, конфиг — `build/gh/config.yml`) |

готовые пакеты платы). Без них тайлы и маршруты не собрать — это следующий
шаг после выгрузки данных.

## Слои приборки

1. `GpsBackend` (C++, готов 13.11.2026): подписка на `gpsd` (TCP 2947,
   JSON TPV/SKY) — позиция, курс, скорость, спутники, hdop; отдаёт в QML
   (карта, камеры) и в сетевой слой — `car.gps` с `valid`/`age_ms` (контракт
   `docs/integration.md`). Устаревание >5 с → `valid = false`.
   Без приёмника тестируется `tools/gps_test_server.py` (тот же протокол
   по TCP); при появлении u-blox M10 — просто `gpsd -n /dev/ttyUSB0`.
2. `MapView` (QML + WebView): MapLibre, стиль под палитру приборки, маркер
   машины со стрелкой курса, режим «карта по курсу»; зум — джойстиком
   ▲/▼ в навигации (z8…15, по умолчанию 14). Здания — слой `building`
   (z14+), подписи улиц — `transportation_name` с SDF-глифами Lato.
3. `RouteService` (C++): запрос к Valhalla, хранение активного маршрута,
   линия на карте, подсказки (манёвр, расстояние, улица, ETA).
4. `NavPanel` (уже есть): плашка манёвра и карточка без карты — остаются,
   только данные теперь свои, а не от Android.

## Ввод адреса без тачскрина

| Способ | Как работает |
|---|---|
| Избранное | «Дом», «Работа», «АЗС», «Мойка» — энкодер листает список, PRESS строит маршрут (13.11.2026) |
| Недавние | последние 10 маршрутов (в памяти сессии; в общем списке после избранного) (13.11.2026) |
| По карте | ◀/▶ сдвигают вид, в центре перекрестие; PRESS = «сюда» (13.11.2026) |
| С телефона | `{"type":"address","text":"…"}` по WebSocket (`/ws`) → поиск в SQLite FTS → маршрут (13.11.2026) |

Управление в навигации (джойстик): ▲/▼ — зум (z8–15), ◀/▶ — сдвиг вида
(появляется перекрестие), энкодер — листать избранное+недавние, PRESS —
маршрут к выбранному пункту или к перекрестию, BACK/NAV — выход.

Поиск адреса — `tools/nav-search.py`: строит `maps/addresses.sqlite`
(SQLite FTS5: дома, названия улиц, города, парки из `district.osm.pbf`).
`tools/tile-server.py` отдаёт его по `/search?q=…&limit=5`; приборка
(и телефон) спрашивают там. База данных — в `maps/` (в git не попадает).

Полноценный ввод текста джойстиком — не делаем: это сотни щелчков.
Формулировка в интерфейсе: «выберите на карте или с телефона».

## Инструмент сборки тайлов: Planetiler (вместо tilemaker)

13.11.2026: tilemaker 2.4.0 не собрался на текущем тулчейне — `Boost::system`
стал header-only, rapidjson 1.1.0 не компилируется GCC 15, с master-rapidjson
вылезает конфликт `namespace boost::sort` с Boost 1.90. Патчить не стали.

Берём **Planetiler** (Java, без сборки, тот же `.mbtiles`):

```bash
# нужен JDK 21: build/toolchain/jdk21
build/toolchain/jdk21/bin/java -Xmx3g -jar build/toolchain/planetiler.jar \
  --osm-path=maps/district.osm.pbf --output=maps/tiles.mbtiles \
  --bounds=36.016,54.855,39.218,56.657 --minzoom=8 --maxzoom=15 \
  --download --force --tmpdir=build/tmp --download_dir=build/toolchain/sources
```

Свои источники (~1.4 ГБ: lake centerlines 80 МБ, natural earth 434 МБ, water
polygons 933 МБ) качает один раз в `build/toolchain/sources/`.

## Решено 13.11.2026: пустая подложка карты

Что было видно: маршрут и CSS-маркер машины рисуются, а подложка (вода,
дороги, здания) — пустой фон. В браузере `map.html` при этом рисовалась.
Причин оказалось **две**, и обе в WebView приложения, а не в тайлах.

**Причина 1 — WebGL заблокирован.** Chromium в QtWebEngine по умолчанию
блокирует WebGL на программном рендерере (llvmpipe/Mesa):
`ContextResult::kFatalFailure: WebGL1 blocklisted`, и MapLibre падает с
`Failed to initialize WebGL` ещё в конструкторе — карта вообще не создаётся,
остаётся только CSS-маркер. В браузере WebGL есть, поэтому там всё
рисовалось.
Фикс: `main.cpp` при старте выставляет
`QTWEBENGINE_CHROMIUM_FLAGS=--ignore-gpu-blocklist` (если флаг ещё не
задан — дописывает, не затирая). Сделано в `main.cpp`, а не в `run.sh`,
потому что на плате приборка стартует из systemd (`deploy/systemd/
dashboard.service`), где `run.sh` не участвует. Проверено: в app-логе
`webgl1: true`, карта создаётся.

**Причина 2 — MapLibre не резолвит относительный URL тайлов.** В
`style.json` было `"tiles": ["/tiles/{z}/{x}/{y}"]`. MapLibre v4.7.1
передаёт этот URL в воркер как есть, и `new Request('/tiles/…')` в воркере
падает: `Failed to parse URL from /tiles/…`; запросы тайлов не уходят
вообще (0 запросов к серверу). Причина — в самом MapLibre: в контексте
воркера `Request` требует абсолютный URL. Карта в браузере рисовалась
на версии с абсолютным адресом тайлов; свежую (относительную) версию в
браузере не перепроверяли, но WebView падал именно из-за этого.
Фикс: в `Dashboard/map/index.html` в конструктор карты добавлен
`transformRequest`, который абсолютизирует любой относительный URL от
`document.baseURI`. Так работает и в браузере, и в WebView, и не зависит
от порта/адреса сервера — `style.json` остался портативным.

Проверено 13.11.2026:
- отдельный WebEngine-харнесс (`qml6` + QtWebView) и проба через CDP
  показывают `webgl1: true`, 9 слоёв, тайлы загружены, на скриншоте
  страницы 26 111 px дорог (`#7E8F9C`) и 3 005 px магистралей (`#BCEAF1`);
- **e2e в приложении**: `--mock --window`, навигация включается по-настоящему
  через `DASHBOARD_INPUT_DEMO=100,nav` (кадр 0x530 → CanBackend →
  InputController), маршрут строится (2.73 км), CDP-проба внутри приложения:
  `webgl1: true`, карта 1920×720, на скриншоте страницы дороги и
  магистрали присутствуют.

Если снова понадобится отладка карты: запустить приложение с
`QTWEBENGINE_REMOTE_DEBUGGING=9222` и прицепиться CDP-пробой (скрипты
лежат в `build/webtest/`, вне git) — она показывает JS-консоль, состояние
карты и скриншот страницы.

Дополнение (13.11.2026, вечер): карта доведена «до улиц и домов».

  отдаёт их как обычную статику.
- Отдельного предупреждения в `MapLibre`: без глифов (`glyphs` в стиле)

## Данные собраны полностью (13.11.2026)

`maps/tiles.mbtiles` — весь bbox «Москва + 100 км», **z8–15**,
448 МБ, 114 433 тайла (~20 минут на этой машине). Собрано
`tools/nav-build-tiles.sh` (planetiler с полным `--bounds`); стиль

**Важно после пересборки тайлов:** уже запущенный `tile-server.py` держит
старый файл открытым — его надо перезапустить (`Ctrl+C` и снова
`./tools/nav-serve.sh`), иначе приложение продолжит получать старые
тайлы.

**Замечание по стилю:** вода (`water`) в стиле рисуется **после**
площадных слоёв (landcover/landuse/park). В данных OSM полигоны парков
заходят на реку, и если рисовать воду первой, Москва-река пропадает под
зелёным — так и было до правки (проверено: слой воды плавал красным,
пока его не перенесли выше).
