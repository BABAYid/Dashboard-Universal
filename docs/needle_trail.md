# Шлейф стрелки — отложенная реализация (ждём новый скин)

**Статус: НЕ реализовано.** Записано по просьбе заказчика 26.10.2026.
Делать, когда дизайнер отдаст новый скин (стрелка + размытый шлейф одним
набором картинок).

## Что хотим

Хвост за стрелкой виден **только пока стрелка меняет положение**. Когда
значение стабилизировалось — шлейф плавно растворяется за 0.3–0.5 с. Это даёт
ощущение инерции/физики, а не «постоянной тени».

Пробовали раньше (шлейф удалён в `f78d378`): MultiEffect, Canvas-сектор с
`createConicGradient` (в этой сборке Qt нет этой функции — заливало сплошным),
`ConicalGradient + OpacityMask` (мягко, но выглядело «инородной плашкой»),
размытая копия арта с догонянием по углу. Основная претензия была не к
механике, а к тому, что тень выглядела чужеродно на фоне арта. Подход ниже
решает это тем, что шлейф — **картинка, нарисованная дизайнером под этот же
арт**, а не сгенерированный примитив.

## Логика (простая и надёжная)

1. Свойство `needleSpeed` — «стрелка движется».
2. При каждом изменении угла стрелки: `needleSpeed = |новый − предыдущий|`,
   перезапуск таймера «успокоилась».
3. Таймер 100 мс: если за это время изменений не было — `needleSpeed = 0`.
4. Прозрачность шлейфа: `needleSpeed > 0.5 ? 1 : 0`, с
   `Behavior on opacity { NumberAnimation { duration: 400; Easing.OutQuad } }`
   — плавное растворение.
5. Шлейф под стрелкой (`z: 1`), стрелка сверху (`z: 2`), цифры — на диске
   под шлейфом (картинкой).

## Скелет для нашего `Dashboard/Gauge.qml`

В нашем коде угол стрелки — `gauge.needleAngle` (расчётный) и
`gauge.sweepAngle` (самопроверка); шлейф должен следовать тому же углу, что и
стрелка, поэтому берём тот же источник, что у `mainNeedle`:

```qml
// --- шлейф (появится с новым скином) ---
property real needleSpeed: 0
property real trailPrevAngle: 0

function trailAngleNow() {
    return gauge.startup ? gauge.sweepAngle : gauge.needleAngle
}

onNeedleAngleChanged: trailTick()
onSweepAngleChanged: trailTick()

function trailTick() {
    const a = trailAngleNow()
    const d = Math.abs(a - trailPrevAngle)
    trailPrevAngle = a
    if (d > 0.01)
        needleSpeed = d
    trailFadeTimer.restart()
}

Timer {
    id: trailFadeTimer
    interval: 100
    onTriggered: needleSpeed = 0
}

Image {
    id: trailImage
    // путь задаст новый скин, например images/trail_spd.png
    source: gauge.trailImageSource
    width: parent.width * gauge.needleScale   // как у mainNeedle — та же поза
    height: width
    x: (parent.width - width) / 2
    y: (parent.height - height) / 2
    fillMode: Image.PreserveAspectFit
    transformOrigin: Item.Center
    rotation: trailAngleNow()
    opacity: needleSpeed > 0.5 ? 1.0 : 0.0
    Behavior on opacity { NumberAnimation { duration: 400; easing.type: Easing.OutQuad } }
    visible: gauge.showTrail && !gauge.startup
    z: 1
}

// основная стрелка — z: 2, объявляется ПОСЛЕ шлейфа
```

Замечания по адаптации к нашему коду (из прошлых итераций):

- **Наклон арта не важен** — шлейф вращается тем же углом и в той же позе,
  что и стрелка, поэтому совпадает автоматически (не нужно подбирать
  «поправку 191°/−79°», как это делалось для нарисованных примитивов).
- Шлейф и стрелку нарисовать **в одной позе и масштабе** (720×720, как
  `needls_*.svg`), иначе при повороте разъедутся.
- Настройка «Шлейф стрелок» (`showTrail`) и флаг `--no-trail` раньше были;
  при возврате — вернуть и они (`Settings.qml`, `savedNeedleTrailEnabled`).

## Что попросить у дизайнера

1. **Стрелка** (SVG, как сейчас `needls_spd.svg`).
2. **Размытый шлейф** — та же стрелка с размытием/градиентом, отдельным
   файлом, в той же позе и на том же холсте 720×720. Прозрачность —
   альфа-каналом.
3. Для малой стрелки (топливо/температура) — свой маленький комплект, если
   для неё тоже хочется шлейф.

Требование к картинке: шлейф должен «таять» уже внутри самого файла
(плавная альфа к хвосту) — тогда в QML остаётся только включать/выключать его
прозрачность по движению.

## Почему это самый надёжный вариант

- никаких Canvas/шейдеров и аппаратных эффектов в рантайме — одна `Image`;
- не мерцает и не грузит рендер (FPS на llvmpipe не менялся в прошлых тестах);
- ровно тот вид, который нарисовал дизайнер, без «инородной плашки»;
- исчезновение в покое задаётся таймером + `Behavior`, а не сложной
  математикой отставания.
