## 1. Что это

Виртуальная приборная панель для автомобиля. Блок сбора на ESP32 читает сигналы
машины и отправляет их по CAN, приборка на RK3588 принимает и рисует.

```
ESP32 (сбор сигналов) ──CAN 500 кбит/с──► RK3588 (SocketCAN) ──► Qt6/QML приборка
```

**Экран:** 1920×720, установка в автомобиль.
**Среда разработки:** Linux (Ubuntu), Qt 6.10, CMake, Make (ninja в системе нет).

### Железо: панель

**Tianma P1230FHF1MAAA**, 12.3", 1920×720, 60 Гц, 1000 нит, рабочая температура
−30…+85 °C. Интерфейс — **2-port LVDS** (нечётный и чётный порты, по 4 пары данных
и тактовой в каждом). Разъём LCD — FH41-50S-0.5SH (50 контактов, шаг 0.5 мм).

Подсветка: **4 канала по 120 мА при 24.8 В** (~11.9 Вт), постоянный ток, в панели
есть термистор для термокомпенсации. Драйвер подсветки поставляет продавец панели;
он обязателен, потому что 12 В от платы меньше 24.8 В линейки светодиодов.

Логика панели — 3.3 В (питание с платы, джампер/перемычка выбора напряжения).

### Железо: плата приборки

Окончательно не выбрана, рассматриваются две (обе RK3588, у обеих двухпортовый
LVDS — панель подходит):

| Плата | CAN | Температура | Питание | Особенности |
|---|---|---|---|---|
| **BTP-PCM-A-A588** | **есть, на борту** | 0…+70 °C (в спецификации «рекомендуется 5…35») | 12 В, 3–5 А | двухпортовый LVDS, RS485, SATA, PCIe, 4G-сокет |
| **BTP-PCM-A-022A** | нет | −20…+70 °C | 12 В, 250–300 мА | двухпортовый LVDS, но CAN только через USB-адаптер |

Решено пробовать на одной из них. Если у A588 не устроит температурный диапазон,
правильный путь на будущее — плата на **RK3588J** (индустриальная версия чипа,
−40…+85 °C) или SoM + своя несущая плата. Обычный RK3588 — коммерческий чип,
поэтому у всех дешёвых плат пределы по холоду.

**Слабое звено по холоду — плата, а не панель:** панель до −30, плата до 0 или −20.
Отсюда рекомендация делать плату съёмным модулем, чтобы потом заменить её одну,
а не всю приборку.

**Важно:** образы ОС в папке `образ для nanoPC-T6/` для этих плат **не подойдут** —
другой загрузчик и дерево устройств. Нужны образы от продавца платы.

## 4. Сборка и запуск

Нужен Qt 6.8+ с модулями Quick и WebView.

```bash
cmake -S Dashboard -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
```

### Запуск

```bash
./build/appDashboard --mock          # демо-режим: данные генерируются, CAN не нужен
./build/appDashboard --can can0      # приём реальных кадров с интерфейса can0
./build/appDashboard --fullscreen    # для установки в автомобиль (без рамки)
```

Отладочный снимок экрана (удобно на устройстве без монитора), задержка в мс:

```bash
DASHBOARD_SHOT=/tmp/dash.png DASHBOARD_SHOT_DELAY=5000 ./build/appDashboard --mock
```

### Тесты

```bash
cmake -S Dashboard -B build -DDASHBOARD_BUILD_TESTS=ON
cmake --build build --target test_canprotocol
./build/test_canprotocol                # проверки разбора
./build/test_canprotocol --mock-watch   # наблюдение за демо-генератором
```

### Подготовка CAN на устройстве

```bash
sudo ip link set can0 up type can bitrate 500000
candump can0            # посмотреть, что приходит от ESP32
ip -details link show can0
```

Если интерфейс появится позже запуска приборки, приложение само подключится
к нему в течение 5 секунд. При отсутствии кадров дольше 1,5 с на экране
загорается предупреждение «НЕТ ДАННЫХ CAN».

## 5. Протокол CAN

Версия 1.1, классический CAN, 11-битный ID, 8 байт данных, 500 кбит/с.
Полное описание — `can_protocol_v1.1.txt` (и `.odt`).
Разбор в коде и документация обязаны совпадать: при изменении расположения
данных поднимать версию протокола и править оба места.

| ID | Период | Содержимое |
|---|---|---|
| `0x100` | 50 мс | скорость (байт 0), обороты (байты 1–2, uint16) |
| `0x200` | 50 мс | байт 0 — свет (поворотники, дальний, ближний, габариты, туманки, задний ход, стопы); байт 1 — индикаторы (чек, ABS, ручник, ремень, давление масла, LOCK) |
| `0x300` | 50 мс | температура двигателя, уровень топлива, напряжение ×10, наружная температура (int8), авария по маслу, расход ×10 (uint16, байты 5–6) |
| `0x400` | 50 мс | режим АКПП (P/R/N/D/L), номер передачи, LOCK, провода S1/S2/SL |
| `0x7F0` | 1000 мс | статус блока сбора: счётчик, версия прошивки, время работы, ошибки шины, XOR |

**Что исправлено в 1.1 относительно 1.0**

- **Расход топлива не влезал в отведённый байт.** В 1.0 объявлен как uint8
  со значением ×10 при диапазоне 0–99.9 л/100 км, то есть требовал 0–999.
  Теперь это uint16 в байтах 5–6.
- **Добавлен кадр `0x7F0`.** Без него приборка не могла отличить перезапуск
  блока сбора от зависания. Приборка считает перезапуски и пишет их в журнал
  (`deviceRestarts`, `deviceFirmware`, `deviceUptimeSec`).
- Дописаны правила контроля свежести данных и приоритеты ID.

Разбор реализован в `Dashboard/can/CanBackend.cpp` и покрыт тестами.

## 6. Лампы и индикаторы

Все лампы управляются данными из CAN и по умолчанию погашены:

| Лампа | Условие |
|---|---|
| Поворотники | мигают 1,5 Гц, пока приходит соответствующий бит `0x200` |
| Дальний свет, габариты, противотуманки | соответствующие биты `0x200` |
| Ремень | бит «не пристёгнут» `0x200` |
| Ручник | бит ручника `0x200` |
| ABS, Check Engine, давление масла | биты `0x200` |
| Топливо | уровень ≤ 10 % (`0x300`) |
| Зарядка АКБ | двигатель работает (обороты > 400), а напряжение < 12,8 В |
| Перегрев двигателя | температура ≥ 110 °C (`0x300`) |

При включении зажигания все лампы горят 2,5 с (самопроверка), стрелки
проходят полную шкалу.

**Значки шкал** (топливо и температура двигателя) — это разметка прибора, а не
лампы: они видны всегда. Мигают только при низком уровне топлива или перегреве.
Не делать их условными — это уже было ошибкой.

## 7. Раскладка макета

Экран 1920×720 разбит на зоны (координаты в `Main.qml`):

| Зона | Где | Что там |
|---|---|---|
| Спидометр | x 0…714, y 3…717 | прибор целиком; в навигации — 0.5 и в левый нижний угол |
| Тахометр | x 1206…1920, y 3…717 | прибор целиком; в навигации — 0.5 и в правый нижний угол |
| Верх центра | x 714…1206, y 20…75 | часы (слева, x 730), лампы (по центру), наружная температура со снежинкой (справа, x 1080) |
| Верх центра, ниже | x 714…1206, y 92…134 | предупреждения: «НЕТ ДАННЫХ CAN» и «ГОЛОЛЁД» |
| Центр | x 714…1206, y 154…558 | переключаемые режимы (`CenterPanel.qml`): стандарт / компьютер / диагностика, внизу точки-индикаторы. Позже сюда же встанет 3D-модель |
| Низ центра | x 714…1206, y 566…650 | показания (напряжение, топливо, температура, расход) и одометр |
| Цифровые значения | внутри каждого прибора, y 230…306 | цифровая скорость и цифровые обороты над ступицей, без подписей единиц |

**Ключевое правило:** вся информация держится в центральной полосе x 714…1206.
Прибор — это круг радиусом 357 с центрами (357, 360) и (1563, 360), поэтому
любая точка ближе этого радиуса попадает на шкалу. Именно так часы и наружная
температура оказались на тахометре — их оттуда убрали.

**Почему приборы уменьшаются и уезжают в нижние углы в навигации:** циферблаты
полупрозрачные (альфа 255 только в центре, на радиусе 300 — уже 16). На чёрном
фоне это незаметно, поверх карты приборы просвечивают и не читаются. Поэтому
карта занимает весь экран, приборы уходят в нижние углы, а под каждым прибором
лежит **непрозрачная чёрная подложка** — она нужна в обоих режимах, иначе под
прибором просвечивают разделительные полосы.

**Полосы-разделители** — картинки 641×5 (натуральный размер, не растягивать;
раньше их сжимали до 500×10 и концы не доходили до приборов). В раскладке ширина
800 с центром на середине: концы заходят под циферблаты и там скрываются
подложкой. В навигации полосы гаснут.

**Про цифры в приборах.** Свободная полоса на циферблате — ровно 79 px прямо
над ступицей (y 230…306). Сверху её подпирает иконка ремня (кончается на y=228),
снизу — иконка передачи (начинается с y=307), поэтому выше и ниже поставить
нельзя. Выше мешают ещё и стрелки: и основная, и топлива/температуры — все четыре
нарисованы одним и тем же длинным рисунком, поэтому стрелка топлива ходит по низу
циферблата (сектор 61°…116°), а не сидит в своём маленьком секторе. Цифры
нарисованы **поверх стрелок** с тонким чёрным контуром (`style: Text.Outline`) —
подложку убрали по просьбе заказчика; контур нужен, потому что стрелка тахометра
проходит через цифры на ~4000 об/мин. Появляются цифры после самопроверки
приборов (первые 2,5 с скрыты).

Кегль цифр — 54 px (высота знака ~45 px, было 33 при кегле 40). Подписи «км/ч»
и «об/мин» убраны: единицы измерения и так очевидны по прибору. Блок сдвинут
вверх на 9 px (`y: parent.height * 0.317`), иначе из-за верхнего просвета шрифта
цифры садятся ниже центра свободной полосы.

**Отдельная находка для дизайна:** в исходниках дизайнера лежит `Стрелка
короткая.svg` — по-видимому, для указателей топлива и температуры. Сейчас в
проекте все четыре стрелки используют один и тот же длинный SVG (файлы
`needls_*.svg` побайтово идентичны). Если поставить короткие стрелки топливу и
температуре, низ циферблатов освободится — например, под крупные цифровые
показания.

**Читаемость поверх карты** обеспечивают: вертикальный градиент затемнения
сверху и снизу, а также отдельная скруглённая подложка под зоной часов (она
слишком далеко от края, градиент до неё не достаёт).

## 8. Геометрия стрелок и шкал

Замерено по исходникам дизайнера — это нужно для любой правки приборов.

**Стрелки.** Все четыре стрелки (`needls_spd/fuel/temp/tho.svg`) — один и тот же
рисунок, и при `rotation = 0` он смотрит **не вверх, а влево**, примерно на 191°.
Поэтому угол поворота считается как `угол_метки_на_шкале − 191.2`:

| Прибор | Положение стрелки | В коде |
|---|---|---|
| Спидометр, 0 км/ч | метка «0» на 135.1° | `speedStartAngle: -56.1` |
| Спидометр, 220 км/ч | метка «220» на 20.3° | `speedEndAngle: 189.1` |
| Тахометр, 0 об/мин | метка «0» на 134.5° | `rpmStartAngle: -56.7` |
| Тахометр, 8000 об/мин | метка «8» на 46.1° | `rpmEndAngle: 214.9` |

Метки шкалы спидометра стоят через 22.29° (по 20 км/ч), метки тахометра — через
33.5° (по 1000 об/мин), «4» тахометра ровно вверху (269.8°).

**Проверка при правке углов:** запустить `./appDashboard` без `--mock`, CAN-данных
нет, все значения нулевые — стрелки должны стоять ровно на нулях шкал.

## 9. Коэффициенты калибровки и жесты

Двойной клик по центральной области открывает окно калибровки (скорость,
обороты, топливо, температура). Значения сохраняются и применяются при запуске.

| Жест | Что делает |
|---|---|
| двойной клик по центру | окно калибровки |
| долгое нажатие по центру | режим навигации (карта) |
| клик по одометру | переключение ODO / TRIP A / TRIP B |
| долгое нажатие на одометре | сброс текущего trip |

**Внимание:** у панели Tianma нет тачскрина, а в машине нет мыши. Значит, эти
жесты на устройстве недоступны — нужен физический вход (кнопки на GPIO платы
или кнопка на руле через ESP32, в кадре `0x200` есть свободные биты).

## 10. Грабли и особенности реализации

То, что уже ловили и починили, но легко вернуть при рефакторинге.

- **CAN читается напрямую через SocketCAN** (`PF_CAN`/`SOCK_RAW`), без
  `Qt6::SerialBus`: этого модуля нет в системе разработки, и он может
  отсутствовать на плате, а формат кадра у нас фиксированный — классический CAN,
  11-битный ID, 8 байт. Достаточно поддержки SocketCAN в ядре.
- **`CanBackend` — QML-синглтон. Его конструктор намеренно объявлен без
  аргумента по умолчанию.** Qt при регистрации синглтона сначала проверяет
  возможность создать объект конструктором по умолчанию и только потом —
  статический `create()`. Если класс default-constructible, QML создаст второй
  экземпляр, и данные в приборку не попадут — молча, без ошибок в логе.
- **Анимации стрелок пишут в отдельное свойство `sweepAngle`, а не в `rotation`:**
  запись в привязанное свойство разрушает привязку, и стрелка «застывает».
- **Абсолютных путей к файлам быть не должно** — только ресурсы QML-модуля.
- **Протокол и документация обязаны совпадать.** При изменении расположения
  данных в кадре — поднимать версию протокола и править оба места.
- **Любая информация в центральной полосе x 714…1206** — см. раздел «Раскладка».

## 11. Решения и компромиссы

«Почему так, а не иначе» — чтобы через полгода не раздумывать заново.

- **SocketCAN вместо QtSerialBus.** Меньше зависимостей на устройстве,
  фиксированный формат кадра, работает везде, где есть поддержка CAN в ядре.
  Для платы без CAN (022A) подойдёт USB-CAN адаптер на `gs_usb`/`slcan` —
  код менять не придётся.
- **WebView для карты (OpenStreetMap), а не нативный рендеринг.** Быстрый старт,
  не нужно тащить тяжёлые библиотеки, но требует интернета (офлайн-карты пока
  не подключены). WebView создаётся **только** при входе в навигацию: иначе
  QtWebEngine поднимает процессы и грузит карту при каждом запуске. Замер памяти:
  приборка без карты ~103 МБ (один процесс), с картой ~507 МБ (четыре процесса).
  При 4 ГБ ОЗУ (вариант A588/022A) запаса хватает с большим избытком, но именно
  карта определяет требования к памяти.
- **Образ ОС — без рабочего стола.** Для приборки нужен Debian/Ubuntu minimal и
  запуск через EGLFS. Образ с GNOME съедает 1–1,5 ГБ и нагружает GPU, который
  нужен для 3D.
- **Приборы уменьшаются в навигации, а не скрываются.** Сохранение контекста
  (скорость/обороты всегда на виду), но требует непрозрачных подложек
  из-за полупрозрачных циферблатов.
- **Демо-режим `--mock`.** Позволяет верстать и тестировать UI без железа и
  без ESP32, что критично, пока прошивки нет. Демо-кадры проходят через тот же
  разбор, что и настоящие.

  частей, анимации отдельными клипами, текстуры ≤2K. Замер: dev-пакет

## 14. История документации

Протокол и таблица пинов приведены в соответствие с железом (v1.1):

- Расход топлива в `0x300` не помещался в uint8 при заявленном диапазоне
  0–99.9 л/100 км ×10 → перенесён в uint16 (байты 5–6), версия протокола 1.1.
- Добавлен кадр статуса блока сбора `0x7F0` и правила контроля свежести данных.
- В таблице пинов были занятые флешем GPIO 6–11, несуществующие GPIO 20/24,
  аналоговые входы на не-АЦП выводах 21/22, входы на strapping-выводах,
  и делитель 10к/3.3к, который при 14.5 В даёт 3.60 В — на пределе абсолютного
  максимума для вывода ESP32. Не было согласования CAN 120 Ом.

Что поправлено в этом файле относительно первой версии: раскладка приведена
к текущей (часы и наружная температура убраны с тахометра в верхнюю зону центра),
добавлен раздел про железо (панель Tianma и платы), уточнено, что карта теперь
на весь экран, полосы скрыты под приборами и гаснут в навигации.
